The final six (C1.10 write-buffer, C1.14 boot-consolidation, F2.1/2.2/2.5/2.6 third-party adapters) landed in a follow-up pass: free plugins (Ninja Forms, LifterLMS, Tutor LMS, PMPro, TranslatePress, Weglot) were installed on Local for true end-to-end verification, then removed; paid ones (LearnDash, MemberPress) ship best-effort drivers against their documented APIs with clean degradation. > Roadmaps 1–4 complete (305 abilities, v0.30.1 live). This roadmap is different in shape: it is **fix-first** — the scan found 3 HIGH-severity security issues, several real bugs, and systematic consistency gaps that must land before new features. Feature waves (R5.F) come last.

## The thesis

- [x] **Hardening**: the plugin hands an AI 305 site-mutating tools. The primitives (path jail, SQL classifier, options denylist) are genuinely strong, but the scan found the snapshot directory readable on nginx, the per-role access gate fail-open, and a privilege-escalation path through delegatable categories. These are the reputation-killers — fix before anything else.
- [x] **Consistency**: 305 abilities grew across 4 roadmaps; the seams show. `destructive` annotations are incoherent, 51 write abilities skip audit logging, confirm gating uses 3 idioms, 16 list abilities have no pagination. One consistency wave makes every future ability cheaper and safer to add.
- [x] **Reach**: verified-absent gaps (undo for content, WP core update, theme upgrader, classic widgets, LMS adapters) are the Roadmap-5 feature story — but they wait their turn.

## 🔴 Wave S1 — Security criticals ✅ COMPLETE 2026-08-10 (+ T1.1 test runner; suite green, 146 files)

> Implementation notes: S1.1 went with a per-site random **directory token** (`wpultra-snapshots-<16hex>`, option `wpultra_dir_token`, old dirs auto-renamed) instead of per-file suffixes — `migration.php` reuses the backup name for its manifest path, so renaming files would have broken restores. S1.2 verifies the hook via `did_action` first, then a source scan of `WP_Ability` (`wpultra_access_execute_hook_fires()`), fails **closed** for non-admin grants, and reports as the `access_gate_wired` self-test check.

- [x] **S1.1 · Snapshot/backup dir web-exposure** 🔴🔥🔥🔥 — `includes/system/siteops.php:579-587` protects `wp-content/uploads/wpultra-snapshots` with `.htaccess` only ("Deny from all") — **ignored on nginx/IIS**. Dumps contain full `wp_users` (password hashes, salts) and filenames are guessable (`snapshot-<Ymd-His>`). Fix: reuse the sandbox hardening pattern from `includes/sandbox/runtime.php:14-39` (`.htaccess` + `web.config` + `index.php`), add a random ≥16-char suffix to snapshot/backup filenames, prefer a path outside webroot when writable. `includes/system/backup.php:150-161` delegates to the same function — one fix covers both.
- [x] **S1.2 · Access gate is fail-open** 🔴🔥🔥🔥 — the entire per-role grant + rate-limit layer hangs on the `wp_before_execute_ability` action (`includes/access/engine.php:208-210`). Nothing verifies the hook actually fires; if the Abilities API renames it, a granted subscriber silently reaches all 305 abilities (baseline `wpultra_permission_callback` returns true once any role holds any grant — `includes/access/engine.php:156-159`). Fix: add a `did_action`/instrumentation assertion to `self-test.php`, AND either move the deny decision into `wpultra_permission_callback()` itself or add a boot-time check that falls back to admin-only when the hook is absent.
- [x] **S1.3 · Never-delegatable list omits privilege-escalation categories** 🔴🔥🔥🔥 — `includes/access/engine.php:44-49` blocks `filesystem`, `code-execution`, `database`, but NOT: `system` → `manage-plugin-theme` `install-plugin` accepts a **zip URL** (= arbitrary PHP, indistinguishable from execute-php); `users` → `manage-user`/`roles-manage` (= mint a new admin); `site-migrate`, `staging-clone`, `option-set`. Fix: add `system` + `users` (or at minimum those five abilities) to `wpultra_access_never_delegatable()`.
- [x] **S1.4 · `delete-plugin`/`update-plugin` have no confirm gate** 🔴🔥🔥🔥 — `includes/abilities/manage-plugin-theme.php` exposes unrecoverable plugin deletion as a single unconfirmed tool call (compare `manage-cron.php`, whose far less dangerous delete IS gated). Add `confirm` to the input schema and gate `delete-plugin`, `delete-theme` (once it exists), and `update-plugin`.

- [x] **S2.7 · `readme.txt` documents the old weaker SQL gate** 🟠🔥 — `readme.txt:45` claims DELETE/UPDATE are destructive only without WHERE and "INSERT is never gated"; the shipped classifier (`includes/helpers.php:50-68`) is allow-list based and gates `INSERT … ON DUPLICATE KEY UPDATE`. - [x] **S2.9 · Case-sensitive path comparison on Windows** 🟠 — `wpultra_path_is_within_directory()` (`includes/helpers.php:26-30`) compares with `str_starts_with`; `realpath()` drive-letter case can differ from `ABSPATH` → spurious `path_outside_base`. - [x] **S2.10 · Public REST endpoints need an opt-out** 🟠🔥 — `wpultra/v1/{chat,track,jserror}` + `wpultra/headless/v1/*` are unauthenticated by design (page-cache beacons), rate-limited only by spoofable `REMOTE_ADDR` transient counters; `/chat` fans out to a paid LLM API. ## Architecture notes

- **Reuse over new code:** S1.1 reuses `sandbox/runtime.php` hardening; S2.1 reuses `dbrepair.php`'s backtick escape; S2.2 reuses `visualdiff.php`'s URL validation; C1.1 rides the same `wp_before_execute_ability` hook as the access gate (and S1.2's assertion protects both); F1.1 extends the existing undo ring, not a new system; F1.3 uses the already-loaded `Theme_Upgrader`; F2.x extend the proven adapter directories. *(All honored.)*
- **Safety pattern unchanged:** destructive = confirm-gated (now via the shared C1.2 helper); every mutation → activity-log (now guaranteed centrally by C1.1); snapshots before repair; never-delegatable expanded (S1.3), never shrunk. *(All honored.)*
- **Self-test as the enforcement layer:** every invariant this roadmap establishes gets a self-test assertion — hook fires (S1.2), manifest ≡ disk (C1.6), confirm-gated ⇒ destructive (C1.3). Regressions surface in `self-test`, not in production. *(All honored.)*
- **Categories:** S/C waves touch existing files; F1 → `system`/`content`/`gutenberg`; F2 → `verticals`/`forms`/`multilingual`/`users`. *(As planned.)*
